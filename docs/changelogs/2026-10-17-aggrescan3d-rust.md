# Aggrescan3D Rust integration — 2026-10-17

NOVA registers Aggrescan3D as a subfilter within Developability. Developability requires its existing TNP criteria and both inclusive whole-VHH A3D caps: mean `<= -0.68002724866200` and peak `<= 1.58023066762925`. A shared profile evaluator enforces the same decision in sync and async paths. The pipeline keeps three stages and attributes A3D rejection or unavailable scoring to `Developability`.

The subfilter reuses the heavy-atom model generated by TNP, using native Rust scoring and pinned FreeSASA 2.0.1 before temporary cleanup. It returns five scores, sequence/structure SHA-256 provenance, method metadata and the original DOI. Nested A3D results include per-cap decisions or explicit errors. TNP measurements remain visible, without repeating prediction.

The native core, input checks, locked dependencies, fixtures and MIT notice are preserved. Native score output now uses round-trip decimals for threshold comparisons. A3D is enabled by default under `config.developability.aggrescan3d`; the installer keeps downloads/builds under ignored `.tools/`. Serving hosts need the native tools on `PATH`. `AGGRESCAN3D_ENABLED=false` explicitly disables A3D checks while retaining TNP criteria.

The original paper is cited in the root guide, native scorer guide, usage guide/BibTeX and every native result: Zambrano et al. (2015), [doi:10.1093/nar/gkv359](https://doi.org/10.1093/nar/gkv359). The related 2019 update is also attributed in the method documentation.

## VHH metric documentation and reusable functions

The operator guide now explains every native metric, per-residue output, whole-VHH versus segment review, FR2/CDR3/interface priorities and the difference between upstream positive AUC and normalized positive burden. It documents full-context scoring before IMGT-based region aggregation, insertion-code mapping, the limits of causal attribution and the distinction between current HTTP output and derived library reports. The original A3D papers and the 2025 VHH regional study are cited with their different purposes made explicit.

New public Rust functions `metrics::summarize_vhh` and `metrics::summarize_region` provide the recommended reporting panel over precomputed scores. Region masks use the full-VHH score order and normalize by the selected residue count. Six boundary tests cover signed cancellation, zero/negative sets, matching full-region results, finite scores, overflow, mask length and empty selections. Regional descriptors remain annotations; only whole-VHH mean and peak enforce A3D rejection.

## Limits and next action

Tests stub TNP structure prediction and earlier diversity/nativeness filters where needed; no GPU-backed predictor was run. Full external-tool test collection requires AbNumber, absent from this local test environment. The fixed caps are screening policy rather than universal physical boundaries.
